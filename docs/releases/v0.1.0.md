## 繁體中文

### 內容、相依與變更

`grok-engineering-workflow` 與 `grok-review-change` 導讀固定 Core 工作流、授權／停止、審查／安全及 exact-head 契約。套件含完整來源與 MIT notices、能力 mapping、consumer evidence envelope、Core lock 及兩個標準函式庫 verifier。Packet 不是原生 Grok API schema。

Core README 與四契約的完整相對引用閉合需要十三檔；新增 CHANGELOG／release notes 隨原 bytes 保留。相對前 pin，九個既有檔案及四份契約不變。更新 code-owned allowlist／revision／十二份 Markdown collection、lock／manifest／引用與受影響測試；二十二個 payload 加 manifest 共二十三檔。既有 parser、no-follow filesystem／fresh-stage 算法、技能、catalog／mapping 及 false flags 不改。Core 與產品版本獨立，使用者不必另裝 Core；runtime 使用固定文件，不追蹤 main 或動態 tag。

依賴為既有 Python 3.10+ 標準函式庫、適用 POSIX 操作、取得固定來源的 Git，及日後管理 plugin 的既有 Grok CLI。macOS 有離線證據，其他 POSIX 未資格化，Windows 不支援。能力目錄 `1.0.52 (0920c8169e27)` 與 2026-10-17 本機 help `1.0.60 (01a8e1c591c0)` 分列，沒有相容版本範圍保證。未交付執行環境、服務、MCP／hooks 或新 API 憑證。

### 取得、安裝、更新與回復

從正式 Release 核對完整產品 commit／tree、annotated tag 及 manifest digest，再取得可信固定來源。用該來源 verifier、獨立取得的 digest 與既有 assembler 組裝全新二十三檔 bundle。來源 archive 含開發文件／測試；不能把來源 PASS 當成封閉安裝樹。詳見 [指定版本入口與最小原生整合](../installation.md#native-integration-zh)。

本次發布不修改用戶安裝。後續由協調者核對精確寫入／ownership、有效 home／leader、trust／enablement、custom／partial 保全及 source copy／registration，再使用官方本地 plugin install，從可信來源驗實際 payload root 的二十三檔／Core closure。遇未知額外內容不刪除或放寬 inventory 強求 PASS；新授權問題保留完整身分並停止轉交。

沒有先前正式產品可供原生降版證明。未發布 candidate 是開發歷史。各版本以自己的 verifier／digest 另組新目標，不能疊放或盲目重播。`--keep-data` 僅記 persistent data 保留，不保證自訂 payload；native atomic update／rollback 未證。不能以卸載當復原。

### 驗證與限制

離線驗證涵蓋兩個受影響 test suites、Core13／package23 exact inventory、digest／mode／完整相對引用、fresh staging／relocation、既有目標保留、stale 身分、缺少新文件及即使重算 package manifest 的 Core 竄改拒絕。新 consumer 完整 diff 的獨立 reviewer、安全掃描、findings disposition、exact-head／平台 gate 與 merge／publication 收據綁於最終 GitHub Release／本地交接；舊準備或 Core scan 不自動套用。未配置的 CI／平台 enforcement 不記為 PASS。

Help、schema、inventory 或 exit 0 不證明原生安裝或模型採用。Native 寫入位置／bookkeeping／信任／copy／preservation 及真正 update／rollback 尚待最小實裝；runtime、skill-loading、delegation、delivery readiness 均 false。[Issue #2](https://github.com/jeffery777/grok-build-dev-skills/issues/2) 是歷史 OPEN、設計完成且非阻擋，不重開 sandbox／deny／resume QA。未驗證不冒稱缺陷；成本／延遲／公司案例／模型等價與完整 ASD-STE100 符合性亦未驗。

### Formal source and content identity

The shared identity table above records product `0.1.0`/tag `v0.1.0`, exact Core tag object, resolved commit/tree, twelve-Markdown and thirteen-file digests, separate LICENSE, raw package-manifest hash and twenty-three-file bundle digest. Read the product's actual full commit/tree/tag object from the [formal GitHub Release](https://github.com/jeffery777/grok-build-dev-skills/releases/tag/v0.1.0) and annotated tag. Source files do not embed their own future commit. The Core tag object is not the pinned commit.

Set algorithm `sha256-path-tab-sha256-lf-v1` sorts UTF-8 path bytes, concatenates `path<TAB>SHA256(raw bytes)<LF>`, then hashes the result. The Core Markdown inventory encoding is 1135 bytes. Check size and 100644 mode separately. Raw manifest hashing differs from set digests and Git commit/tag identity. Compressed source-archive container hashes are not calculated and do not equal raw-file-set identities.

### Contents, dependencies and changes

`grok-engineering-workflow` and `grok-review-change` guide fixed Core workflow, authority/stops, review/security and exact-head contracts. The bundle retains complete sources/MIT notices, capability mapping, consumer evidence envelope, lock and two standard-library verifiers. Packets are not native Grok API schemas.

README plus the four Core contracts reach all thirteen files, including exact new CHANGELOG/release notes. Nine existing files and all four contracts retain bytes. Code-owned allowlist/revision/twelve-Markdown collection, lock/manifest, references and affected tests change together. The bundle has twenty-two payload files plus manifest, twenty-three total. Parser, no-follow filesystem/fresh-staging algorithms, skill bodies, catalog/mapping and false flags remain. Product and Core versions are independent. Core needs no separate installation, and runtime never follows main or dynamic tags.

Dependencies are existing Python 3.10+ standard-library support, suitable POSIX operations, Git for fixed-source retrieval and an existing Grok CLI for later management. macOS has offline evidence; other POSIX systems are unqualified and Windows is unsupported. Catalog `1.0.52 (0920c8169e27)` differs from local help `1.0.60 (01a8e1c591c0)` observed on 2026-10-17. No compatibility range, runtime, service, MCP/hooks or new API credential is supplied.

### Retrieval, installation, updates and recovery

Each version uses its own verifier/digest and a fresh target without overlays or blind replay. `--keep-data` documents persistent data only, not custom-payload protection. Native atomic update/rollback is unproved; uninstall is not recovery.

### Verification and limits

Offline checks cover both affected suites, exact Core 13/package 23 inventories, digests/modes/complete relative references, fresh staging/relocation, existing-target preservation, stale identities, missing new documents and Core tampering despite rewritten package hashes. Independent review, security scanning/findings, exact-head/platform gates and merge/publication readbacks cover the final complete consumer diff through formal Release/local receipts. Old Core/preparation scans do not automatically apply. Unconfigured CI/enforcement is not PASS.

Help, schema, inventory and exit 0 prove neither native installation nor model adoption. Actual writes/bookkeeping/trust/copy/preservation and native update/rollback remain later minimum integration. Runtime, skill-loading, delegation and delivery readiness stay false. [Issue #2](https://github.com/jeffery777/grok-build-dev-skills/issues/2) is design-complete historical OPEN tracking, nonblocking here; sandbox/deny/resume QA is not reopened.
