## English

[Issue #32](https://github.com/jeffery777/grok-build-dev-skills/issues/32) closes the Local plugin upgrade-delivery gap left by 0.2.0. This document and version strings do not establish publication; read back the annotated tag, full source commit and [GitHub Release](https://github.com/jeffery777/grok-build-dev-skills/releases).

A native-created single-product Grok 1.0.62 fixture rejected same-source reinstallation. Under explicit authorization, preservation of old source/payload and fixed new source, native single-product uninstall with `--keep-data`, zero-registration readback and fixed-version installation produced exactly one 0.2.1 registration and all thirty files. Each operation ran once with a 20-second execution budget and 131072-byte combined-output acceptance limit. No model or index operation ran. See [evidence](../verification/local-plugin-upgrade.md) and [preconditions/stops](../installation.md).

Only the product-version literal, its test expectation, derived manifest and delivery documents change. There is no new installer or generic migration framework. Skills, controller, Core, source locks, dependencies and [MIT notices](../provenance/upstream-notices.md) are unchanged. GitNexus 1.6.12 scope remains that of 0.2.0. The identity table above applies to both languages.

The result does not qualify production installation, new capability trust, model adoption, vendor features, multi-product/custom-data migration, downgrade or atomic rollback. The observed empty-registry gate applies only to a home with one repo and one product. Stop before source replacement or uninstall when other repos coexist; that route requires a separate current plan/acceptance. If installation fails after uninstall, no active plugin may remain; preserve state and stop without automatic retry/recovery. Production adoption still requires formal fixed sources, exact scope and fresh applicable trust. Runtime, skill-loading, delegation and delivery readiness remain false. Existing 0.2.0 notes, tags and Release are retained.
